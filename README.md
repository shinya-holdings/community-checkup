# 次に声をかける3人

コミュニティの発言ログから、**伸びしろのある人**と**離れかけている人**を見つけるツールです。

HTMLファイル1つで動きます。インストールもアカウント登録も要りません。

**→ [ツールを開く](https://shinya-holdings.github.io/community-checkup/)**

---

## なぜ作ったか

Discordで6ヶ月かけて5,000人の方に参加していただきました。
NFTのセールが延期になり、1週間で500人が離れていきました。

集まるのは1日28人。離れるのは1日71人。
**崩れる速度は、集まる速度の2.5倍でした。**

残ったのは1,000人。でも振り返ると、最初から話してくれていたのは1,000人だった。
いなくなったのではなく、**最初から届いていなかった**んです。

当時「今日チャット流れてないな」としか思っていませんでした。
数字を数えたのは、後になってからです。

このツールは、そのとき見ておくべきだったものを出します。

---

## 何が出るか

診断して終わりではなく、**誰に何をするか**まで出します。

| 出るもの | 判定 |
|---|---|
| **次に声をかける3人** | 発言はあるが中心にはいない。他の人とやり取りしていて、複数の日に顔を出している人 |
| **中核メンバー** | いま支えてくれている人。抜けると目に見えて盛り上がらなくなる |
| **発言が止まった人** | 2回以上発言していたのに、途中から途切れた人。離脱の予兆 |
| **一度きりで戻っていない人** | 最初の1回に返事がつかなかった可能性が高い |
| **まだ一度も発言していない人** | 人数（メンバー数を入力した場合） |

あわせて、発言の中身から**その人が何をしている人か**を推定します。
「話題を出す人」「答える人」「迎える人」「繋ぐ人」「場を温める人」「頼られている人」の6種類です。

### 月ごとに分けて見る

**1か月の結果より、月から月への動きのほうが情報量があります。**

月ごとの内訳表に、発言数（前月比つき）・発言した人数・**新規発言者**・
**その月で発言が止まった人**・中核が占める割合を並べます。
行を選ぶと、上の4つのリストがその月だけの結果に切り替わります。
「先月の候補が、今月は中核に上がっているか」を追えます。

### イベントの前後を比べる

イベントの日付と名前を入れると、**前後でチャットがどう動いたか**を出します。
何件でも登録できます。前後の日数（3／7／14／30日）は選べます。

| 出るもの | 意味 |
|---|---|
| 平均発言数の変化 | 前後の日数が違っても比べられる形で見る |
| 当日の発言数・発言した人数 | 盛り上がったかどうか |
| **イベント後の新規発言者** | イベントが人を連れてきたかどうか |

日ごとの発言数のグラフに、イベントの日が縦線で入ります。
**発言は増えたのに新規発言者が0人**なら、いつもの人が盛り上がっただけで輪は広がっていません。
そこまで出します。

### 報告書としてダウンロードする

結果を1つのファイルにまとめて書き出せます。**HTML** と **Markdown** の2種類です。

| 形式 | 用途 |
|---|---|
| HTML | ファイル1つで完結。ブラウザの印刷から PDF にできます。そのまま渡せます |
| Markdown | Notion や議事録、GitHub に貼るとき |

中身は、全体の数字・日ごとの動き・月ごとの内訳・イベントの前後・4つの人のリストと
それぞれへの「やること」・月ごとの「次に声をかける3人」（付録）です。
**画面で選んでいる期間に関わらず、すべて入ります。**
一部だけの資料を渡すと、受け取った側が前提を確かめられないためです。

冒頭に「この数字の前提」（除外した発言数・日付の扱い・推定であること）と、
末尾に「この報告書の限界」を必ず入れています。

> **社外に渡す前に**「名前を伏せて表示する」にチェックを入れてください。
> 外したままだと実名で書き出します。画面にもそう出ます。
> 伏せ字は**人ごとに固定**なので、表とリストを突き合わせて読めます。

## 使い方

1. コミュニティの発言ログを読み込む（ドラッグ＆ドロップ、または貼り付け）
2. **運営・コミュニティマネージャーにチェックを入れて外す**
3. イベントの日付と名前を入れる（任意。前後の比較が出ます）
4. メンバー数を入れる（任意）
5. 分析する

### 対応している形式

| 形式 | 例 |
|---|---|
| `.txt` | Discordの画面からコピーして保存したもの |
| `.docx` | Wordに貼り付けたもの |
| `.csv` | 投稿者・日時・本文の列があるもの |
| `.json` | DiscordChatExporter の書き出し |
| `.html` | 同上 |
| 貼り付け | Discordの画面から直接コピー |

CSV は見出し行から列を判断します。`AuthorID` のような**ID列は名前として使いません**
（数字の羅列が名前として並んでしまうため）。

### 複数のファイルをまとめて読み込む

**何ファイルでも読み込めます。** チャンネルごと・期間ごとに書き出したログを、1つの結果にまとめます。
ドラッグ＆ドロップは一度に複数選べます。あとから足すこともできます。

読み込んだファイルは一覧で表示され、件数と期間が出ます。「外す」で個別に取り消せます。
同じ名前のファイルを読み直すと、二重にならず差し替わります。

まとめるときに、次の3つを自動で処理します。

| すること | なぜ |
|---|---|
| **同じ発言を重複として除く** | 期間の重なった書き出しを2つ読むと、同じ発言が二重に数えられる。投稿者・日時・本文が一致するものを同一とみなす |
| **時刻順に並べ替える** | ファイルごとに固まっていると、日ごと・月ごとの集計がずれる。日付が全件そろっているときだけ並べ替える |
| **会話の続きの判定を、同じログの中に閉じる** | 別チャンネルの発言が時刻順で隣り合っただけなのに、「答える人」と数えてしまうため |

3つ目は影響が大きいところです。雑談と質問のチャンネルを一緒に読み込むと、
質問チャンネルの1分後に雑談で発言した人が、**まったく無関係なのに「答える人」になります。**
同じログの中だけで隣接を見ることで、これを防いでいます。

> **期間が違うファイルを混ぜると注意が要ります。**
> 片方だけが覆っている期間があると、月ごとの増減とイベント前後の比較が実態とずれます。
> 期間の食い違いは自動で検出して、画面と報告書に警告を出します。

> **同じ人が別名で数えられることがあります。**
> 書き出しの形式によって表示名とユーザー名が入れ替わるためです。
> 「2. 運営を外す」の名前一覧に**似た名前が2つ並んでいないか**確認してください。
> これは自動では直せません。

### 日付の扱い

タイムゾーン付きの日時（DiscordChatExporter の書き出しなど）は、
**お使いの端末のタイムゾーンに直してから**日ごと・月ごとに数えます。

UTC 表記のまま数えると、日本時間の 0時台の発言が前日・前月に入ってしまいます。
元日の朝のあいさつが12月に計上される、といったずれが実際に起きます。

### 運営を外してください

運営やコミュニティマネージャーは、投稿するのが仕事です。
外さないまま数えると必ず中核に入り、「一部に偏っている」という結果になります。

運営を外すと、順位が入れ替わることがあります。
運営の発言に埋もれて、メンバーの中の主力が見えなくなっているためです。

「運営」「公式」「管理」「オーナー」「マネージャー」などを含む名前は、最初から自動でチェックが入ります。

## プライバシーについて

- **すべてブラウザの中だけで計算しています。** ログはどこにも送信されず、保存もされません
- サーバーもデータベースもありません。ファイルを開いた時点で、通信は発生しません
- **生成AIにログを送ってはいません。** 役割の推定も、ブラウザ内の文字列処理で行っています
- 入力したイベント名・日付も同じです。外には出ません
- 書き出す画像に**個人名は含めません**
- 画面のスクリーンショットを共有する場合は「名前を伏せて表示する」を使ってください

---

## 精度について

役割の推定は、日本語の言い回しと会話の並びから判定しています。
**あくまで傾向で、外れることもあります。** 最終的にはご自身の目で確かめてください。

判定がおかしいと感じたら、[Issues](../../issues) で教えてください。
実例をもとにパターンを足していきます。
